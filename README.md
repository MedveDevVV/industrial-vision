# Industrial Vision

Программный модуль технического зрения для анализа видеопотока промышленного мобильного роботизированного комплекса.

Приложение обрабатывает видеопоток, обнаруживает людей, отслеживает их перемещение, определяет нахождение в контролируемых зонах, проверяет наличие средств индивидуальной защиты и формирует события о нарушениях.

## Реализованные возможности

- Захват видеопотока с камеры или из видеофайла.
- Обнаружение людей с помощью YOLO11n.
- Отслеживание объектов с присвоением Track ID.
- Поддержка ByteTrack и BoT-SORT с ReID.
- Настройка контролируемой зоны ROI с помощью многоугольника.
- Определение нахождения человека в зоне по нижней центральной точке рамки обнаружения.
- Временное подтверждение нахождения человека в запретной зоне.
- Проверка наличия каски и сигнального жилета с помощью отдельной модели YOLO.
- Определение отсутствия каски и жилета.
- Анализ СИЗ отдельно для каждого обнаруженного человека.
- Ограничение анализа СИЗ по минимальной высоте человека в кадре.
- Временное подтверждение нарушений, связанных с отсутствием СИЗ.
- Отображение результатов обнаружения и анализа СИЗ на видеопотоке.
- Журналирование обнаруженных нарушений.

## Установка и настройка

Клонируйте репозиторий:

```bash
git clone https://github.com/MedveDevVV/industrial-vision.git
cd industrial-vision
```

Создайте виртуальное окружение:

## Конфигурация

Основные настройки приложения находятся в `configs/configuration.yaml`.

В конфигурации задаются:
- название приложения и уровень журналирования;
- источник видеопотока и параметры повторного подключения;
- путь к модели обнаружения людей и порог уверенности;
- интервал обработки кадров;
- включение и координаты контролируемой зоны ROI;
- используемый алгоритм отслеживания;
- параметры модели СИЗ и условия анализа.

Пример настройки трекера:

```yaml
tracking:
  tracker: bytetrack
```

Доступны два варианта:

- `bytetrack` — ByteTrack;
- `botsort` — BoT-SORT с включённым ReID.

Параметры каждого алгоритма находятся в отдельных файлах каталога `configs/trackers/`.

Для переключения алгоритма достаточно изменить значение `tracker` в конфигурации.

Координаты ROI задаются в нормализованном формате от 0 до 1 относительно ширины и высоты кадра.

Параметры контроля СИЗ находятся в разделе `ppe`. Они позволяют включать и отключать анализ, задавать путь к модели, порог уверенности, минимальную высоту человека в кадре и количество последовательных подтверждений нарушения.

## Запуск приложения

Из корня проекта с активированным виртуальным окружением выполните:

```bash
python -m src.main
```

Для запуска с указанием видеофайла:

```bash
python -m src.main --source "path/to/video.mp4"
```

Интервал обработки кадров можно задать параметром `--update-interval` в миллисекундах:

```bash
python -m src.main --source "path/to/video.mp4" --update-interval 50
```

Если источник не указан, приложение использует значение из `configs/configuration.yaml`.

## Логика обработки событий

Для определения попадания человека в контролируемую зону используется нижняя центральная точка его рамки обнаружения (bbox).

Событие о нахождении человека в запретной зоне формируется после подтверждения его присутствия в ROI на нескольких последовательных обработанных кадрах.

Отслеживание объектов и аналитика событий разделены: трекер присваивает Track ID, а аналитический модуль использует полученные данные для определения нарушений.

### Контроль средств индивидуальной защиты

Для проверки СИЗ используется двухэтапная архитектура:

1. Основная модель обнаруживает человека и определяет его положение в кадре.
2. Для каждого подходящего по размеру человека выделяется область изображения (crop).
3. Отдельная модель YOLO анализирует выделенную область и определяет наличие или отсутствие каски и сигнального жилета.
4. Результаты анализа связываются с Track ID соответствующего человека.
5. Аналитический модуль проверяет результаты и формирует события о нарушениях.

Модель СИЗ распознаёт четыре класса:

- `helmet` — каска;
- `no_helmet` — отсутствие каски;
- `vest` — сигнальный жилет;
- `no_vest` — отсутствие сигнального жилета.

Если размер человека в кадре меньше заданного минимального значения, анализ СИЗ для него не выполняется.

Нарушение не формируется по результату одного кадра. Оно должно быть подтверждено на заданном количестве последовательных обработанных кадров.

Если модель не смогла определить состояние СИЗ, результат считается неопределённым (`UNKNOWN`). Неопределённость сама по себе не считается нарушением.

## Эксперименты с порогом уверенности

В рамках пятого этапа разработки проведено сравнение качества обнаружения людей при разных значениях порога уверенности.

| Порог уверенности | Precision | Recall | F1 |
|---:|---:|---:|---:|
| 0.30 | 0.971 | 0.823 | 0.891 |
| 0.50 | 0.989 | 0.767 | 0.864 |
| 0.70 | 1.000 | 0.665 | 0.799 |

По результатам эксперимента выбран порог `0.30`, обеспечивающий наилучшее значение F1 среди проверенных вариантов.

## Архитектура

Архитектурная схема и её исходное описание находятся в каталоге `docs/`.

Основной конвейер обработки:

1. Захват видеопотока.
2. Получение нового кадра из буфера.
3. Обнаружение людей нейросетевой моделью.
4. Отслеживание объектов и присвоение Track ID.
5. Анализ СИЗ для обнаруженных людей подходящего размера.
6. Проверка нахождения объектов в контролируемой зоне.
7. Подтверждение и формирование событий.
8. Отображение результатов и журналирование нарушений.

Проект разрабатывается поэтапно в соответствии с методическими рекомендациями.
